# Паспорт безопасности цифрового деканата

«Цифровой деканат будущего», конкурсный прототип «Деканат». Проверка проведена 22 ноября 2026 года по московскому времени.

Базовая защита подтверждена на изолированном HTTPS-стенде с синтетическими данными. Оценка конкурсной конфигурации относится к одной реплике production-образа за Caddy с локальным каталогом помощника.

## Область проверки

В область входят вход, профиль и сессии, учебные данные, заявки и PDF, входящие, публикации, физкультура, библиотека, поликлиника, ВУЦ, помощник и резервное копирование. Проверялись действия гостя, двух студентов из разных групп и двух студентов одной группы. ФИО, номера, оценки, расписание, справки и учётные записи синтетические. Исходники требований и воспроизводимых проверок доступны в [MASTER-SPEC](MASTER-SPEC.md#3-изоляция-сессии-и-http-контракт), [инструкции стенда](local-development.md#изоляция-студентов-одной-группы) и журнале.

## Архитектура и доверие

- Браузер обращается к одному HTTPS-домену. Caddy завершает TLS и проксирует запросы к Next.js, приложение обращается к PostgreSQL внутри сети Compose. Публичное приложение не требует внешней модели. Совместное размещение с Qwen сохраняет отдельный процесс модели и отдельный шлюз. [Compose](../compose.yaml) · [Перенос на сервер](server-migration.md)
- Личность, статус аккаунта и группа проверяются сервером по записи сессии. Личные запросы используют идентификатор студента из этой записи. Групповые сведения фильтруются по аудитории и времени публикации. Повторный переход на связанную запись проверяет доступ по правилам целевого ресурса. [Сессии](../src/server/auth/service.ts) · [Требования](MASTER-SPEC.md#3-изоляция-сессии-и-http-контракт)
- Секреты передаются через серверное окружение. Для миграций и приложения используются разные роли БД. PostgreSQL хранит хеши паролей и токенов сессии. [Роли БД](../infra/init-db.sh) · [Конфигурация переноса](server-migration.md#1-подготовить-релиз-и-окружение)

## Результаты прогонов

- На первом стенде с двумя экземплярами приложения прошли production-сборка, TypeScript и 355 тестов Vitest. Playwright подтвердил 36 из 41 сценария с учётом адресных повторов с прежним учебным набором и часами кампуса после публикации решений. Два серверных сценария проверены отдельно через API для ВУЦ и услуг. Запись аудита
- После добавления лимита обе конфигурации Caddy прошли `caddy validate`. На новой конфигурации прошли 11 сценариев Playwright для границы размера, сессий, входа, заявок и PDF. Повторно прошли 355 тестов Vitest, TypeScript и проверка клиентских файлов и логов на известные тестовые секреты. [Регрессия размера](../tests/e2e/request-size.spec.ts) · Запись изменения
