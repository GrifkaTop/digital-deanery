# Загрузка документов для помощника

Хранилище предназначено для общих синтетических документов, доступных всем студентам после входа. Обработка выполняется вручную перед публикацией. Действующие выдержки и ссылка на оригинал доступны в помощнике после публикации.

| Путь | Содержимое |
| --- | --- |
| `inbox/<id>/manifest.json` | Реквизиты документа, режим OCR, ключевые слова и при необходимости график выплат. |
| `inbox/<id>/original.pdf` | Исходный PDF, который передаётся на обработку. |
| `versions/<id>/<revision>/` | Подготовленная версия с `original.pdf`, `document.md` и `index.json`. |
| `examples/library-loans/` | Синтетический PDF о библиотечном абонементе и манифест для пробного импорта. |
| `examples/scholarship-payments-2026-27/` | Синтетическая редакция приказа УС-02, которая переносит декабрьскую выплату на 23 декабря. |
| `sources/*.json` | Компактные исходники документов, проверяемые общей схемой и собираемые PDF-конвертером. |
| `questions.json` | Короткий ручной набор вопросов для проверки поиска и ответов. |
| `generated/<id>/` | Версионируемые PDF и import manifest, собранные из соответствующего исходника. |

По умолчанию Compose использует каталог `documents/`. На сервере можно задать `ASSISTANT_DOCUMENTS_DIR` с абсолютным путём в окружении Compose. Создайте в нём `inbox/` и `versions/` с доступом для пользователя `node` контейнера импорта (UID 1000). Приложение монтирует только `versions/` в режиме чтения. `inbox/` и `versions/` исключены из Git. В резервную копию включайте базу PostgreSQL вместе с `versions/`, чтобы после восстановления запись каталога указывала на существующий PDF.

## Сборка исходников

Текущий согласованный контракт и разрешённые ID перечислены в `src/contracts/document-source.ts` и `docs/MASTER-SPEC.md`. В репозитории есть документы первой очереди, УЧ-03 и УЧ-04, а также обзорные документы УЧ-05—УЧ-09 и ЖС-01—ЖС-02, СТ-01, ОП-01, ОТ-01, ВР-01, ПР-01 и СС-01. Наличие JSON/PDF означает подготовленный синтетический материал, а не опубликованную редакцию; опубликованность проверяется по базе и поиску стенда.

УЧ-05—УЧ-07 и документы третьей очереди дают только обзор общих принципов: они не устанавливают выдуманные санкции, сроки обращений, суммы, скидки, места, формы заявлений, контакты или индивидуальные решения. УЧ-08 перечисляет дисциплины, обнаруженные в синтетическом seed, но не является набором рабочих программ: в seed нет утверждённых результатов обучения, тематик и критериев по каждой дисциплине. УЧ-09 фиксирует, что события консультаций и рубежных контролей в seed отсутствуют, и не является расписанием. Личный график обычных занятий показывается только существующим модулем расписания; вопросы о консультациях, контролях, практике и ВКР не должны получать даты из ближайшего обычного занятия. СС-01 описывает наблюдаемые функции кабинета и не придумывает реальные подразделения или контакты.

Исходники лежат в `sources/<id>.json`. Общий формат: синтетические реквизиты, ключевые слова, автономные разделы и при необходимости выплаты. Один короткий JSON — один документ; одинаковые заголовки, номера или ID запрещены. PDF использует единый шаблон и явно помечается как учебный синтетический материал. Это не юридическая экспертиза: перед показом сверяйте тексты с действующими актами РФ и локальными актами вымышленной организации. При любом расхождении имеют приоритет обязательные нормы РФ. Даты графиков и программ нельзя придумывать из общей сетки расписания; общий каталог не является персональным расписанием.

```sh
npm run documents:build
npm run documents:build -- scholarship-policy-2026-27
```

Команда без ID собирает весь комплект; с ID — только изменённый документ. Результат сохраняется в `generated/<id>/` и копируется в `inbox/<id>/`; имеющийся результат не перезаписывается без явного `--force`. Первые выходные PDF и манифесты можно просматривать и передавать вместе с исходниками. Каждый раздел должен помещаться на одной странице: если сборщик сообщает о переполнении, сократите текст или разделите его на отдельные разделы и повторите сборку. Проверка выполняется до перезаписи существующих файлов. После сборки запустите `npm run documents -- prepare <id>`, сверьте распознанный `versions/<id>/<revision>/document.md` с PDF и лишь затем опубликуйте соответствующую ревизию. Сборка не меняет базу и не публикует документы.

В комплекте УС-02 сохраняет активную дату за декабрь — 24 декабря 2026. `examples/scholarship-payments-2026-27/` с датой 23 декабря — отдельная проверочная редакция, не входящая в комплект. Не копируйте её в рабочий `inbox` для обычной публикации.

Существующий пример библиотечного абонемента сохраняет номер ББ-01. Новые расширенные правила имеют номер ББ-02 от 18 ноября 2026 и повторяют те же 14-дневный срок и одно продление на 7 дней при отсутствии брони; их публикация не заменяет ББ-01.

## Подготовка стенда

На запущенном стенде из корня репозитория выполните:

```sh
docker compose --profile tools build app migrate document-import
docker compose run --rm --no-deps migrate
docker compose up -d --no-deps --wait app
```

На чистом стенде поднимите базу и выполните обычную настройку проекта по [инструкции локального запуска](../docs/local-development.md). Образ импорта включает Poppler и Tesseract с русским и английским языками. Сервис запускается вручную.

## Подготовка и публикация PDF

1. Создайте `inbox/<id>/` и положите туда PDF под именем `original.pdf`. Используйте строчные латинские буквы, цифры и дефисы в `id`. При замене документа сохраняйте тот же `id`.
2. Создайте `manifest.json` по образцу ниже. Указывайте дату утверждения документа в формате `ГГГГ-ММ-ДД`. Режим `auto` включает OCR на страницах без читаемых букв или цифр в текстовом слое. Укажите `always`, если текстовый слой скана даёт неверный результат.

   ```json
   {
     "title": "Положение о библиотечном абонементе",
     "number": "ББ-01",
     "issuedOn": "2026-10-05",
     "synthetic": true,
     "ocr": "auto",
     "keywords": ["библиотека", "продлить", "книга", "вернуть"]
   }
   ```

   `keywords` необязательны. Добавляйте характерные термины и синонимы, например «книга» для документа, где используется «учебная литература». Когда термин относится к конкретной странице, используйте `"pageKeywords": [{"page": 2, "keywords": ["продлить", "вернуть"]}]`. Полнотекстовый поиск учитывает также название и извлечённый текст.

3. Подготовьте выбранный документ или всю входную папку:

   ```sh
   docker compose run --rm --no-deps document-import prepare library-loans
   docker compose run --rm --no-deps document-import prepare
   ```

   Команда выводит идентификатор и хеш версии. При повторном запуске с тем же PDF, манифестом и форматом импорта используется уже подготовленная версия.
4. Откройте `versions/<id>/<revision>/document.md` и сравните его с PDF. Проверьте важные даты, цифры, таблицы и номера страниц. Для исправления замените PDF или скорректируйте манифест во входной папке и повторите подготовку. Каталоги версий служат архивом готовых артефактов.
5. Опубликуйте проверенную версию. Вместо `REVISION` вставьте хеш из вывода `prepare`.

   ```sh
   docker compose run --rm --no-deps document-import publish library-loans REVISION
   ```

6. Войдите в кабинет и задайте вопрос с характерными словами из документа. Для примера подойдёт «Как продлить библиотечный абонемент?». Откройте ссылку на найденную страницу и проверьте оригинал PDF.
7. Прогоните относящиеся к документам вопросы из `questions.json`: прямые, разговорные, составные и об отсутствующих сведениях. Убедитесь, что ссылка ведёт к нужному пункту; ответы общего каталога не раскрывают личные оценки, статусы выплат, стоимость или индивидуальные даты.

Перед публикацией зафиксируйте дату и ссылки правовой сверки, область применимости и ограничения в `sources/LEGAL-BASIS.md`. Сверьте PDF, извлечённый `document.md`, JSON-манифест, номер редакции и контрольные вопросы. Проверьте целевую БД и хеши опубликованных редакций read-only. `prepare` не публикует документ; только после этих проверок допускается `publish <id> <revision>`. Проверьте поиск и PDF после входа, затем повторите прямой доступ после выхода. Не удаляйте более ранние каталоги `versions/<id>/<revision>/`.

Чтобы сразу попробовать готовый пример, скопируйте `examples/library-loans/` как папку `inbox/library-loans/` и выполните шаги 3–6. Публикация заменяет активную редакцию целиком. Ссылки привязаны к хешу, поэтому после смены редакции ссылки на предыдущую версию больше не открываются. Для отката передайте в `publish` хеш прежней версии. Чтобы убрать документ из поиска и закрыть его ссылки, используйте:

```sh
docker compose run --rm --no-deps document-import withdraw library-loans
```

Файлы подготовленных версий остаются на диске после отзыва.

## Публикация графика выплат

Для приказа с графиком добавьте в манифест массив `payments`. `month` обозначает месяц начисления, `payOn` — дату перечисления, `page` — номер страницы оригинального PDF начиная с 1. Например, если декабрьскую стипендию перечисляют в январе, запись выглядит так.

```json
{ "month": "2026-12", "payOn": "2027-01-05", "page": 2 }
```

Перед публикацией сверьте каждый месяц, дату и страницу с оригиналом. Команда подготовки проверяет, что на указанной странице есть извлечённый текст. Публикация применяет весь график одним действием и возвращает ошибку, если месяц уже занят другим приказом. При замене укажите прежний ID и включите в манифест все выплаты, которые остаются в силе.

Для отдельной проверки скопируйте `examples/scholarship-payments-2026-27/` в `inbox/scholarship-payments-2026-27/`, выполните `prepare` и `publish` с этим ID. Миграция добавляет исходный учебный текст приказа УС-02 с датой 24 декабря. Пример PDF заменяет его редакцией с датой 23 декабря и добавляет ссылку на оригинал. Следующий вопрос «Когда стипендия за декабрь?» сразу использует опубликованную дату.

## Реестр доступности на локальном стенде

Состояние сверено с базой 18 ноября 2026 года. «Вопрос» — контрольная формулировка из `questions.json`; она помогает проверять связь с поиском, но само наличие вопроса не гарантирует, что любой вариант формулировки будет найден. Публикации доступны после входа. Статусы относятся к указанному стенду и не заменяют проверку после восстановления или переноса.

| Источник | Статус | Контрольный вопрос или примечание |
| --- | --- | --- |
| УС-01 | Встроенный ответ | `stipend-definition`, `stipend-conditions`; подготовленный PDF не подключён к встроенной карточке. |
| УС-02 | Опубликован | `payout-date`; действующая редакция в базе без PDF. |
| УЧ-01 | Встроенный ответ | `combined-calendar`; подготовленный PDF не подключён к встроенной карточке. |
| ББ-01 | Опубликован с PDF | `library-renewal`; существующее положение об абонементе. |
| ББ-02 | Опубликован с PDF | `library-renewal`; расширенные библиотечные правила. |
| СП-01 | Опубликован с PDF | `certificate`, `certificate-paper-form`; исправленная редакция. |
| УЧ-02 | Опубликован с PDF | `consultation`; исправленная редакция. |
| УЧ-03 | Опубликован с PDF | `assessment-direct`, `assessment-colloquial`. |
| УЧ-04 | Опубликован с PDF | `debt-colloquial`, `debt-date-absent`. |
| УЧ-05 | Опубликован с PDF | `attendance-direct`, `attendance-colloquial`. |
| УЧ-06 | Опубликован с PDF | `appeal-direct`, `appeal-combined`. |
| УЧ-07 | Опубликован с PDF | `materials-direct`. |
| УЧ-08 | Опубликован с PDF | `program-combined`; обзор имеющихся дисциплин, не рабочие программы. |
| УЧ-09 | Опубликован с PDF | `consultation-direct`; сообщает об отсутствии дат событий. |
| ЖС-01 | Опубликован с PDF | `leave-direct`. |
| ЖС-02 | Опубликован с PDF | `transfer-combined`. |
| СТ-01 | Опубликован с PDF | `social-direct`. |
| ОП-01 | Опубликован с PDF | `tuition-colloquial`; персональные суммы отсутствуют. |
| ОТ-01 | Опубликован с PDF | `dorm-absent`; данные о местах и стоимости отсутствуют. |
| ВР-01 | Опубликован с PDF | `conduct-requests`. |
| ПР-01 | Опубликован с PDF | `practice-direct`; персональные назначения и даты отсутствуют. |
| СС-01 | Опубликован с PDF | `service-map`; реальных контактов нет. |

Архив: прежние подготовленные редакции сохраняются в `versions/<id>/<revision>/`; они не являются действующими публикациями и не выдаются как текущие документы. Исходные PDF СП-01 и УЧ-02 с обнаруженными расхождениями — архивные. Пример изменения даты УС-02 в `examples/` — отдельная проверочная редакция, она не действует на стенде. Подготовленные файлы УС-01 и УЧ-01 не опубликованы как файловые редакции и остаются подготовленными артефактами для будущего подключения к встроенным ответам.

Будущие материалы: полные рабочие программы отдельных дисциплин и график консультаций и рубежных контролей. Их содержание и события не подтверждены данными приложения; обзор УЧ-08 и справка УЧ-09 не выдаются за эти будущие документы.
